`test_connection_indicator.py` runs the existing hidden runner and e2e scene driver. Every HUD state has its own case at 640x360, 960x540, 1280x720 and 1920x1080. Good has only the milliseconds line on the HUD; every Seats state retains its hint. Every Seats case has four seats in four different states and checks every column on the host and clients. Four additional held-seat cases stall the fourth seat through the existing live-stall lever and assert its rendered name appears once; host rows are checked across every page. The quality lever deliberately makes 250 ms Good and 80 ms Substituting. Exact strings and RGB expectations are written independently of the presentation functions.

The native picture assertions measure text, containment, overlapping controls and ink read from the rendered frame. Each case retains both the HUD bitmap and composited frame. F6 presses and releases have two drawn frames between them. Drop-down selection uses the existing framed HandPick gesture. The toggle case saves Off, relaunches into a match with no badge and the full Seats column, then saves On and relaunches again before checking the badge. Single-engine relaunches bind `CCCP_SETTINGSPATH` to the retained runtime's own settings file, check the saved property after every selection, and read Off before selecting On. A missing property or incomplete probe fails. The cold-load budget is `--timeout 240`; menu exit waits for the probe's done signal and a refresh, not a startup wall-clock timer.

The single-player guard calls the existing two-boolean binding `ActivityMan:PauseActivity(true, true)` at its fourth tick, captures the whole composited frame and compares all RGB pixels to the baseline. Its probe remains scheduled through the paused menu loop and asserts the fixture's actual activity name, so a title screen cannot satisfy it. There is no tolerance or mask. Both probes must complete and both real images must exist at the requested size. The baseline guard is the unchanged reference; it cannot honestly be a failing test of its own pixels.

Run the driver with `--repo <TIP_TREE> --baseline-repo <BASE_TREE> --out <NEW_OUTPUT> --peer-boxes host=<BOX>,seat2=<BOX>,seat3=<BOX>,seat4=<BOX> --host-address <HOST_ADDRESS> --pool-registry <BOX_REGISTRY>`. The baseline checkout must be 107dbdab7c7d780d40f6be4fb8f27e49db9e7a3a and hold its verified executable. A single-engine assignment uses `--single-engine` and reports the multiplayer pictures as NEEDS TESTING. It never starts extra peers on that box or reports them green.

For a layout detector, add `--layout-detector` and explicitly assign the four seats to one or two boxes, for example `--peer-boxes host=<BOX>,seat2=<BOX>,seat3=<BOX>,seat4=<BOX>`. The e2e scene driver passes `share_ok=True` and does not declare the layout peers reviewed for network proof; readback, native memory limits and task ownership checks remain. Detector result JSON and capture metadata say `topology: single-box` and `proof: false` even when every layout assertion passes. Four separately assigned boxes without this flag remain the proof mode; shared-box pictures are never network evidence.

Before any engine starts, the driver finds ffmpeg on PATH or in the coordinating box's configured runner `path_prepend` directories, including those in `--pool-registry` or the usual box-facts file. That prefix is passed to the e2e subprocess, as the remote runner prepends it to its payload. A missing encoder fails with the box name, registry and missing runner PATH prefix, and writes a failed result without losing a launched picture set.

The suite gate compares tip and exact baseline results on the same box. Existing baseline red rows remain recorded; a new red row on the tip fails. The lead's run agent performs both suite invocations and compares the row names and first failing lines.
