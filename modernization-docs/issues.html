Found by cortex-modern build-test (2026-05-17) — the two-stage FoW branch crashes on game start

Not an upstream-filed issue — a bug we discovered by building and running the two-stage Fog-of-War branch (dynamic-fow-negative-distance-test; see Upstream Branches). The branch builds clean (0 errors), but starting any Fog-of-War match crashes on the first simulation frame.

  • Symptom: EXCEPTION_ACCESS_VIOLATION in RTE::SceneLayer::GetBitmap; the game aborts and dumps AbortLog.txt / AbortScreen.png.
  • Repro: build the branch (Debug Full / x64), then Scenario Battle → Skirmish Defense → Metra Plains with Fog of War enabled → crash on start.
  • Callstack: MovableMan::Update (MovableMan.cpp:1327) → SceneMan::CommitToLastSeenTerrainWithFowMask (SceneMan.cpp:939) → Scene::GetUnseenLayerMask(team) returns nullptr → ->GetBitmap() dereferences null.
  • Root cause: the activity reports Fog of War enabled, so MovableMan::Update runs the per-player FoW commit — but the per-team unseen layer (m_apUnseenLayerMask[team]) was never created for that human player's team. CommitToLastSeenTerrainWithFowMask has no null-guard, although its sibling MakeAllUnseen does. Same root as the branch's splitscreen gap — per-team FoW setup is only half-wired.
  • Fix: minimal — null-guard CommitToLastSeenTerrainWithFowMask (early-return when the layer is null), matching MakeAllUnseen's existing style. Proper — ensure the per-team unseen layers are created, with a valid resolution, for every team participating in a Fog-of-War-enabled activity.
  • Impact: the #1 blocker to shipping two-stage FoW — the branch is not playable for a standard FoW match as it stands, so this must be fixed before the feature can land for Release 7.
