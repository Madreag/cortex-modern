ADR-001 Fork strategy — cortex-modern + modernization-effort Accepted

2026-05-16

Context

We need an independent working repository to modernize the engine without disrupting upstream, and a clear, named starting point.

Decision

Fork cortex-command-community/Cortex-Command-Community-Project to Madreag/cortex-modern. The official repo is tracked as the upstream git remote; our fork is origin. All initial work happens on branch modernization-effort, cut from development @ 41e6b7010.

ADR-002 Keep LuaJIT 2.1 — do not migrate to Luau or Lua 5.4 Accepted

2026-05-16

Context

The engine is on LuaJIT 2.1 (Lua 5.1.4 dialect, frozen language). Luau (typed Lua) and Lua 5.4 are tempting modern targets.

Decision

Stay on LuaJIT 2.1. Bump it to the current rolling release for the CVE-2024-25176 fix, but keep the runtime.

Consequences

We retain JIT + FFI performance and do not fracture the existing mod ecosystem — ~53K LOC of community Lua is all 5.1-dialect. The real scripting liability is luabind, not LuaJIT (see ADR-003).

ADR-003 Replace luabind 0.7.1 with sol2/sol3 Proposed

2026-05-16 · dev-review correction (2026-05-17): the upstream lead confirms the sol3 branch compiles but is not functional — sol2 changes usertype property/constructor semantics (sol2 issue #1513) and breaks vanilla and modded Lua. Re-executing it as-is collides with ADR-004; the real cost is a compatibility shim. Reassess whether this migration is worth doing at all.

Context

luabind 0.7.1 is abandoned, Boost-dependent, blocks toolchain upgrades, and forces build hacks (no PCH, re-enabling C++17-removed features).

Decision (proposed — pending an effort spike)

Migrate the Lua binding layer to sol2/sol3. Use the stalled upstream sol3 branch as a reference for the shape of the work, not as a merge base.

Consequences

Removes the worst dependency and the Boost requirement. ~5,100 LOC of bindings + the execution core. Main risk is binding-semantics / ownership parity. Tracked as T2-02.

ADR-004 Modernization is incremental and mod-compatible by default Accepted

2026-05-16

Context

Upstream is a very small team with documented mod-compatibility paralysis; large breaking PRs sit for years and rot. We must not reproduce that failure mode.

Decision

Every change ships as a small, independently-mergeable unit. Any change to the mod-facing INI/Lua surface that breaks existing mods requires its own ADR and a migration path. [ARCH] items are sliced into shippable increments before work starts.

Consequences

Slower headline progress, but work actually lands and stays mergeable. This is the governing principle for the whole Roadmap.

ADR-005 Do not duplicate upstream's active branches Accepted

2026-05-16 · dev-review correction (2026-05-17): the upstream lead advises against a Box2D physics switch outright — CC's atom physics is core identity, the box2d-emscripten physics layer never matured, and a real port would need extensive CC-specific work. T3-01 should parallelize the existing atom-travel loop, not adopt Box2D.

Context

box2d-emscripten, gpu-renderer and dynamic-two-stage-fow are the upstream branches with the most recent activity. A later per-branch deep-dive — see Upstream Branches and ADR-009 — refined this: none is truly active, and emscripten-port / interpolated-render-redux proved stale.

Decision

Do not start competing implementations of Box2D physics, the next-gen renderer, or the web port. For physics multithreading (T3-01), parallelize the existing atom-travel loop — not a Box2D switch (see the dev-review correction above). We may revive stalled, un-owned branches (sol3, hot-reloading).

Consequences

Avoids wasted effort and merge conflicts. Focuses our work on genuinely un-owned gaps.

ADR-008 Fork-first development — upstreaming is opportunistic, never a gate Accepted

2026-05-16

Context

Upstream (CCCP) merges PRs very slowly — some sit open for years. Gating our progress on upstream review would stall the effort indefinitely.

Decision

cortex-modern is the primary product. All work happens continuously on the modernization-effort integration branch (features via short feature/* branches, merged in at our own review bar). development is kept as a clean mirror of upstream/development and is never committed to directly. Upstreaming is optional and downstream: to offer a feature we cut a pr/* branch from upstream/development, cherry-pick that feature's commits, and open a small self-contained PR — only when we choose to. We never block ongoing work waiting on upstream, and we sync upstream/development into the integration branch regularly to avoid drift.

Consequences

We are never blocked on the maintainers; upstream merges become a bonus, not a dependency. The cost is our own review discipline and periodic upstream syncs. This resolves the former "Upstreaming" open question.

2026-05-16 · updated 2026-05-17 after a live branch re-check (see the refreshed Upstream Branches page). Two corrections: (1) per the dev-review correction to ADR-003, the sol3 branch is not a re-executable template — T2-02 treats it as a reference only, and the vanilla/mod compatibility break is the real work; (2) the two-stage fog-of-war work has moved to a newer, active branch (dynamic-fow-negative-distance-test), and interpolated-render-redux is being kept current by the lead dev rather than abandoned — it is no longer “ignore”. · Harvest stance amended by ADR-017 (2026-05-18): "track, don't duplicate" is upgraded to "harvest at full speed" — whether a branch's author is active or dormant is irrelevant to our cadence. Context

A commit-and-diff deep-dive of every upstream branch (see Upstream Branches). development has been frozen since 2026-04-06; the branches are unmerged, mostly single-author WIP, and none is mergeable as-is.

Track, don't duplicate — gpu-renderer, box2d-emscripten and dynamic-two-stage-fow: watch them, and adopt if/when they stabilise rather than building our own. ADR-010 Corefall cross-pollination posture — harvest the mod tier, leave the sim Accepted

2026-05-16

Context

A full read of Corefall's milestone specs (M1–M49), cross-checked against the Cortex Command engine source, produced 145 candidate ideas — see Corefall Ideas. ADR-007 deferred this decision until Corefall had a defined architecture; it now does.

Decision

Adopt Corefall ideas only as fresh, clean-room implementations, and concentrate on the moddable side. Pursue the [MOD] tier — AI/squad depth, causal damage and afflictions, loot and perks, factions, missions and storytellers, the traits/morale/memory colony layer — as ordinary Cortex Command .rte mods, forming a feature track parallel to the engine Roadmap. Do not adopt the [ARCH] deep-simulation pillars (atmospherics, material cellular-automata, thermal, vehicle/fluid physics) — they are Corefall's identity and rebuilding them here is wasted effort. The one enabling [CODE] investment worth making is widening the Lua API and adding a custom-property mechanism, which converts further clusters of ideas into pure mod work.

Consequences

cortex-modern gains a large, low-risk content backlog that needs no engine fork. The clean-room boundary is strict and one-directional: ideas may flow Corefall → cortex-modern, but no Cortex Command (AGPL) code or assets may ever enter Corefall (Apache/MIT). Extends and closes ADR-007.

ADR-011 Multiplayer — accept upstream's removal; do not revive netcode Superseded

2026-05-16 · Superseded by ADR-013 — the multiplayer question was reopened for full investigation; see the Multiplayer page.

Context

Upstream removed multiplayer outright — commit "RIP Multiplayer 2019-2025" (2025-01-11); the changelog reads "Removed multiplayer. The existing multiplayer implementation was terrible and broken." All four networking files (NetworkServer, NetworkClient, MultiplayerGame, MultiplayerServerLobby) are commented out of the Meson build; only RakNet is still linked. The old model was server-authoritative screen-streaming, and the per-pixel atom physics is hostile to deterministic lockstep netcode.

Decision

cortex-modern accepts the removal and will not revive networked multiplayer. Local co-op is covered by upstream's multiseat (multi-mouse / multi-keyboard) work, which arrives on the next upstream sync; remote play is left to Parsec / Steam Remote Play, as upstream intends. The dead networking files and the now-purposeless RakNet dependency are deleted as cleanup — this is what T1-03 becomes.

Consequences

T1-03 simplifies from a decision into a pure deletion task; T3-04 ("decide multiplayer's future") is resolved and closed. Networked multiplayer stays a non-goal unless the physics determinism calculus changes. Resolves the former "Multiplayer" open question.

ADR-012 The campaign — a committed strategic + tactical flagship Accepted

2026-05-17 · accepted (was Proposed, 2026-05-16)

Context

Cortex Command ships one campaign — "Conquest", the Metagame — and the shipping game's own notice (MainMenuGUI.cpp, ShowMetaGameNoticeScreen()) calls it "very INCOMPLETE and flawed", promises a ground-up rework that has no code behind it, and redirects players to the Void Wanderers mod. The campaign is the #2 community complaint after AI. With the AI overhaul (ADR-014) and Multiplayer (ADR-015) committed, the campaign was the last open flagship question.

A full investigation produced the Campaign page: a direct source read of the Metagame (rules welded into a ~6,000-line MetagameGUI, coin-flip auto-resolution, no persistence, no content format); a study of Void Wanderers, the community's de-facto campaign; the in-game lore and the Android Arts / Data fluff doc — which revealed a dev-canonical but unfinished story arc (the Bombies, the sentient Orange Dummy CPU, "Star System Death", Uzira, the Mu-ilaak finale) marked "Awaiting cleanup!" and never shipped; and the Corefall campaign design. Ten campaign designs were narrowed to six combined visions and ranked.

Decision

Make the campaign cortex-modern's third committed flagship. The chosen design is "The Frontier": a hybrid — Conquest's strategic war map, fixed and evolved, with a persistent tactical mercenary-company campaign hanging off it; a RimWorld-style storyteller pacing it; neutral factions (a five-step disposition track) and neutral bosses as first-class actors; and the game's own unfinished story, finished, as the anchor-mission spine. It is built as a new Data/Campaign.rte/ on the GAScripted + GlobalScript contract — overwhelmingly [MOD], no engine fork for layers L0–L5. The build is seven dependency-ordered milestones (M0–M6), agent-driven, gated by the CMP campaign-trust suite, no human-time estimates. Binding points: M0 extracts the metagame model out of MetagameGUI before anything else; M1 ships "Conquest, Rebuilt" as a standalone release that retires the in-game apology notice; the anchor missions use the dev-canonical lore; neutral factions and bosses are first-class; Void Wanderers is not forked — it is mined and kept green in the AI flagship's CI mod corpus; the grand-strategy depth is opt-in, off by default; progression is horizontal; the campaign save rides .ccsave on the determinism-island contract. The Campaign page is the living plan and the artifact an implementer builds from.

Consequences

The campaign is the capstone flagship — it consumes the other two. It rides ADR-014's order vocabulary, squad coordination, decision-event channel and replay (the AI makes its battles worth fighting); co-op campaign is Multiplayer's M4; and it shares the AI / Multiplayer M0 harness, the .ccsave path and the determinism contract — one harness, three flagships. It is mostly [MOD] and needs no engine fork. It finishes Cortex Command's scrapped story, which is the campaign's identity differentiator. Void Wanderers continues as a separate, CI-tracked mod. This supersedes ADR-012's own Proposed form and resolves the last open flagship decision; the six-vision analysis, the architecture, the milestones and the validation suite live on the Campaign page.

ADR-013 Multiplayer reopened — investigate before deleting Accepted

2026-05-16 · update: the Multiplayer page has since been expanded from the original four-tier menu into a ranked seven-option solution space, and the determinism / lockstep path is now assessed as a reachable ceiling rather than foreclosed. The multiplayer direction is now decided in ADR-015.

Context

ADR-011 accepted upstream's removal of multiplayer and proposed deleting the dead networking code. That was reconsidered: networked multiplayer is a real, wanted feature, and the option space — from a zero-effort streaming stopgap to a full server-authoritative rebuild — deserved a proper investigation before any code was discarded. A three-part study (the CC source and removal history, Corefall's netcode design, the wider netcode landscape) was carried out; the result is the Multiplayer page.

Reopen the multiplayer question; ADR-011 is superseded. The Multiplayer page holds the full four-tier option analysis; choosing among those tiers is the next decision and will get its own ADR. The determinism-rewrite tier (lockstep — the Corefall approach) is noted as effectively a new engine and is not on the table.

Consequences

No networking code is deleted until a direction is set. RakNet stays as a (harmless) build dependency until a revival picks its replacement transport. cortex-modern keeps networked multiplayer as a live, tracked option — tracked as T3-04.

ADR-014 The AI overhaul — a committed, locomotion-first plan Accepted

2026-05-16 · re-scoped 2026-05-17 after upstream-dev (Causeless) review and a full read of the AI source. The original draft mis-diagnosed the AI — it proposed a layered-hybrid decision architecture (utility AI, HTN, influence maps, a D* Lite pathfinder rewrite) for what is really an execution problem, and it proposed navigation work the v7 development branch had already shipped. The decision below is the corrected, source-verified plan; the AI page is the living artifact.

Context

AI quality is the #1 community complaint and has been for twenty years; the upstream lead has openly called it "garbage". It is also the foundation under the other two flagship efforts — the Campaign is only as good as its battles, and co-op Multiplayer runs enemy AI server-side. A full read of the AI source (the ~5,830-line Lua AI plus the C++ pathfinder, controller and harness) and an upstream-dev review produced a verified diagnosis: the player-visible failures — actors flying into walls, jamming on terrain, killing themselves — are failures of execution (locomotion, path-following, stuck-recovery), not of high-level decision-making, which is adequate. The pathfinder is async, jump-aware and capable, and was recently overhauled; it is not the problem.

Decision

Make the AI overhaul cortex-modern's flagship and first major build. Approach: locomotion-first — improve the existing Lua AI rather than replace it. Rework the path-follower (GoToWpt), add diagnosed stuck-recovery and a hazard-reflex layer, build real squad coordination, and make a focused perception / weapon-choice / orders pass. The engine work is small and bounded: an emergency-interrupt, a danger query, a decision-event channel for observability, a wider order vocabulary. No pathfinder rewrite (MicroPather stays); no utility-AI / HTN / influence-map / behaviour-tree tower. Seven dependency-ordered milestones (M0–M6), beginning with the validation harness, gated by an automated trust suite. The build is agent-driven, sequenced by dependency and validation; "done" is the machine-measured definition on the AI page.

Consequences

The AI is the substrate beneath ADR-012 (the Campaign) and ADR-015 (Multiplayer) — both depend on competent AI. It is mostly [MOD] (Lua) work with a small set of [CODE] engine additions; MicroPather and the existing pathfinder are kept. T1-06 is superseded — it becomes the roadmap's pointer to this flagship rather than a standalone Tier-1 item. Existing mods keep working through a preserved compatibility surface (the command-API facade plus an opt-in legacy AI profile). The AI page is the living plan and the artifact an implementer builds from.

ADR-015 Multiplayer — server-authoritative state replication, staged Accepted

Sequencing amended by ADR-016 (2026-05-18): the architectural commitment in this ADR stands — per-mode netcode on a deterministic core. The order in which the foundation is built changed from M1 server spine + grow-the-island to determinism-first M1–M5 then per-mode adapters M6–M10. The text below is the historical 2026-05-17 record; see ADR-016 for the new sequence and rationale (Teardown recantation, corefall lock, Factorio precedent, performance-ceiling argument).

2026-05-16 · dev-review note (2026-05-17): the upstream lead's review finds full determinism materially more reachable than this decision first assumed — the RNG is constant-seeded, the threading has the SyncedUpdate boundary, modern FP is consistent. That re-prices the determinism retrofit (M5) and rollback PvP (M6) downward; it does not change the staged architecture — state-replication co-op still ships first, since it needs only the terrain island while lockstep needs the whole mod corpus deterministic. The M0 determinism spike measures the remaining cost. See the Multiplayer page.

Context

ADR-013 reopened the multiplayer question and commissioned the full option analysis on the Multiplayer page. Cortex Command's old networking — server-side screen-streaming over RakNet — was removed in January 2025 and cannot be revived: the integration hooks were stripped from five managers, and the per-player 8-bit render path it depended on is gone. The investigation — a direct read of the engine source and the removal history, the comparable games (Teardown, Terraria, Noita, Factorio), and Corefall's netcode design — produced a ranked seven-option solution space. The owner has committed to the recommended path, in full.

Decision

Make networked multiplayer cortex-modern's second committed flagship, after the AI overhaul. Architecture: server-authoritative state replication, staged. One authoritative simulation — a player's host or a headless cortex-server, built into the game and community-hostable; clients send input, predict their own actor, and reconcile. Terrain destruction is replicated as semantic commands over a determinism island, never as pixels. The work is sequenced as seven dependency-ordered milestones (M0–M6): a Steam Remote Play stopgap and the sync harness; the headless server spine; terrain replication; entity replication and co-op prediction; co-op shipped; the whole-tick determinism island; and rollback PvP. Lockstep / rollback is reached by growing the determinism island, not started cold. No human-time estimates — the build is agent-driven, sequenced by dependency and gated by an automated per-tick-checksum harness. The Multiplayer page is the living plan and the artifact an implementer builds from.

Consequences

Co-op ships at milestone M4; competitive PvP at M6. RakNet is retired at M1; the ~5,900 lines of removed networking code are kept as a reference until then, and T1-03 (delete the dead networking code) is absorbed into this flagship rather than actioned separately. The determinism retrofit — chiefly the Lua mod corpus and the threaded sim — is the plan's named risk and is isolated in M5; mod hash sync is mandatory. Multiplayer shares the AI overhaul's M0 observability harness and depends on competent server-side AI (ADR-014), so it is sequenced to ride that work. This resolves the multiplayer direction ADR-013 left open.

ADR-016 Multiplayer sequencing pivot — determinism foundation first, then per-mode netcode Accepted

2026-05-18

Context

ADR-015 committed to server-authoritative state replication with a growing determinism island (M1 server spine → M2 terrain → M3 entities → M4 co-op ship → M5 determinism → M6 rollback PvP). Deeper research surfaced three pieces of 2026 evidence that the staging optimizes for the wrong thing:

  • Teardown creator Dennis Gustafsson recanted publicly in the same blog post the wiki cited as architectural blueprint: "Early on, I dismissed the idea of full determinism for the entire engine (a view I have since reevaluated)" — the Teardown team is moving past their shipped hybrid.
  • The corefall sibling project locked the per-mode-netcode-on-deterministic-core architecture in DR-052 (2026-05-06). cortex-modern was the only one of the two projects deferring determinism.
  • Factorio's deterministic lockstep ships ~500 kbit/s/client at thousands of entities; the cap on actor count becomes the slowest client's CPU rather than one host's, uncapped when M4 multi-threads sim across cores.

Decision

Restructure the MP roadmap to determinism-first ordering with per-mode netcode on top. The new sequence is M1 pre-determinism cleanup → M2 LuaJIT deterministic iteration → M3 fixed-point atom physics → M4 multi-threaded sim with deterministic merge → M5 cross-platform / WASM canonical anchor → M6 server spine + GNS transport → M7 online co-op SHIP (first user-visible) → M8 LAN lockstep SHIP → M9 GGPO rollback PvP SHIP → M10 public hosting (stretch). First MP user-visible ship slips from ~M4 to ~M7 (~6 months); in exchange the performance ceiling on actors, physics, and terrain destruction becomes uncapped (every client runs the full multi-threaded sim in parallel), four MP modes ship instead of two, and the determinism foundation is permanent.

The ADR-015 architectural commitment stands — per-mode netcode (lockstep / prediction / rollback) on a deterministic core. ADR-016 changes the order in which the foundation under that architecture is built.

Consequences

M1–M5 are foundation work (no user-visible MP); M6 enables; M7–M9 ship MP modes; M10 is stretch. Every M1–M5 milestone delivers single-player value (better stability, deterministic replays, fixed-point terrain perf, 4–8× sim throughput from threading, WASM web build), so the pivot is value-positive at every stage even if MP work pauses. Pivot is reversible at any milestone — M1 work alone strengthens single-player; original ADR-015 ordering remains a viable fallback. See multiplayer.html §10 for the full reasoning.

ADR-017 Engine modernization runs as parallel side tracks alongside MP Accepted

2026-05-18

Context

The MP main spine (M1–M10, per ADR-016) handles the determinism-critical engine work directly: the LuaJIT patch (M2), fixed-point atom physics (M3), deterministic threaded sim (M4), WASM anchor (M5), GNS transport (M6). But several engine modernization concerns sit outside the determinism island and don't gate MP shipping: render-frame-rate decoupling, the Camera/RenderBatch abstraction, GPU-accelerated cosmetic systems, comprehensive CLI test surface. Each of these has a substantial upstream branch (often dormant) that's worth mining: interpolated-render-redux (Causeless, active), gpu-renderer (HeliumAnt, dormant), box2d-emscripten (WASM half, dormant), the original interpolated-render (abandoned but useful reference).

Decision

Run engine modernization as five parallel side tracks alongside the MP main spine, each with explicit dependencies and "pairs with" milestones:

  • T-RENDER-INTERP — collaborate with Causeless on interpolated-render-redux. M1 Block C (stable MOID iteration) overlaps with his MOID-stability work; coordinate to avoid double-effort.
  • T-RENDER-GPU — harvest Camera + RenderBatch from HeliumAnt's gpu-renderer branch selectively (no wholesale merge; HeliumAnt is dormant).
  • T-WASM-BUILD — fused into M5; harvest the WASM build scaffold from box2d-emscripten (drop the Box2D physics half per ADR-005).
  • T-COSMETIC — GPU offload of particle / post-process / audio mixing systems; lands alongside M7 so first MP ship benefits from the CPU savings.
  • T-VALIDATION — cccp-ctl CLI test surface modeled on corefall's cfctl spec; grows incrementally with each MP milestone.

None of these side tracks gate MP. If a side track stalls, MP continues. Each side track delivers independent single-player value when it lands. Full plan, timeline visualization, what-ships-when table, risk/fallback paths, and coordination strategy live in engine.html.

Consequences

The engineering effort can run multiple workstreams in parallel without blocking. MP main spine is well-defined (M1–M10 per ADR-016). Side tracks can be picked up by other contributors (or AI agents) when the MP main spine is between deliverables. Causeless's active branch is treated as a coordination opportunity (talk before duplicating); HeliumAnt's dormant branch is a fixed artifact to mine. ADR-005 (no Box2D physics switch) is honored — only the WASM half of box2d-emscripten is harvested.

Open questions — decisions still needed

  • MP M1 Block C harvest scope: how much of Causeless's interpolated-render-redux MOID-stability work cherry-picks cleanly vs needs rewriting for our determinism CI gate? Decided during execution; see D:\Projects\M1_PLAN.md Block C.
  • Transport library lock-in (MP M6): GNS or ENet? Current lean is GNS for the feature set (encryption, NAT, lanes, Steam Datagram Relay when on Steam). Re-confirm before opening the M6 PR.
  • Mod-determinism disclosure timing: post the contract on the CCCP forum / Discord after M2 closes (LuaJIT patch invisible to mods) and again after M4 closes (Lua collision callback shift to end-of-tick — the one mod-visible change). One-way disclosure, not negotiation, per ADR-017.
  • T-RENDER-GPU pickup timing: start the harvest from HeliumAnt's gpu-renderer when MP M5 closes (capacity-permitting) or run it in parallel earlier? Side track per ADR-017; flexible by contributor capacity.
  • Tier-3 sequencing: if/when we take on an [ARCH] item beyond the MP critical path, which first — and does the palette decouple (T3-02) justify its risk?
  • FMOD: keep the proprietary FMOD blob, or move to an open-source audio engine for a fully-FOSS build?
