Foundations

The AI Overhaul

Cortex Command's AI is the game's most-cited weakness. This page is the committed plan to fix it — built from a full read of the AI source on our branch. It covers: how the AI actually works today; what the recent navigation overhaul already fixed; what is still broken and exactly why; the locomotion-first plan; the (small) engine work; what it means for mods; the milestones from here to a finished AI; and how the result is validated automatically. It is written to be built from — an engineer or an AI coding agent should be able to read this page and start.

The headline

AI quality is the #1 complaint across Steam reviews, the forums and mod.io, and it has been for twenty years — old reviews still bite (GameSpy: "terrible AI"; NoobFeed: "units will get stuck or mess up or even die due to a flaw in the AI"). The live upstream tracker carries it now: #208 squad logic, #121 post-rework sentries that twitch and aim randomly, #100 squads that can't fire gatling guns. And the project lead, Causeless, said it himself in the dev Discord (2025-08-09): "the AI is such garbage. it's very frustrating. I want to just fucking delete all the path following code."

That last line is the diagnosis in the developer's own words. Players call the AI “stupid” because they watch actors fly into walls, jam on terrain and kill themselves — a failure of path-following and locomotion, of carrying out a decision, not of making one. This overhaul leads with that, builds milestone by milestone, and is gated by an automated test suite. The flagship is recorded as ADR-014.

How this page was built — and verified

An earlier draft of this page was reviewed by the upstream project lead (Causeless), who found it mis-diagnosed the AI — it applied prestige decision-making techniques to a problem that is really one of execution, and it proposed work that was either wrong or already done. The page was then rewritten against a direct read of the engine source: Data/Base.rte/AI/*.lua (the ~5,800-line Lua AI), Source/System/PathFinder.cpp, Controller.cpp, MovableMan.cpp, and CHANGELOG.md. Every claim below is checked against that source. The corrections that mattered:

  • The navigation overhaul already happened. The v7 development branch this fork is built on already shipped jump-aware pathfinding, jetpack-aware crab/human navigation and smarter digging (§1.7). The plan builds on that — it does not redo it.
  • Jump height is not faked. Actor.JumpHeight is a real per-actor value (jetpack thrust vs. weight) passed into the pathfinder; the FLT_MAX sentinel is only the “flying” value for craft.
  • The pathfinder is one of the stronger parts of the AI — fully async, multithreaded, and cheap to react to terrain changes. It is not being rewritten.
  • The -- abort to avoid memory leaks comment and the // I hate this copy busy-wait are stray, harmless artefacts — not architectural signals.

The result: §3–§7 lead with locomotion, stuck-recovery and reflexes, then squad coordination and a focused perception / decision pass — and drop the earlier utility-AI / HTN / influence-map / pathfinder-rewrite tower. The validation harness (§8) is kept.

1  ·  How the AI works today

Before fixing it, see it clearly. Everything below is from a direct read of the AI source on our branch: ~5,830 lines of Lua under Data/Base.rte/AI/, plus the C++ pathfinder, the controller abstraction and the threaded invocation harness. The shape that emerges explains both why the AI is so moddable and where the real weakness lies.

1.1   The execution pipeline

Every AI actor is ticked through the same seven-step path:

C++ Controller::ShouldUpdateAIThisFrame()
Throttle. An actor's AI runs only every AIUpdateInterval sim ticks (default 2), and actors are spread across ticks by ID (contiguousActorID % interval == simTick % interval). There is no emergency interrupt — a falling actor waits its turn like everyone else.
C++ MovableMan::UpdateControllers()
Dispatch. Runs ThreadedUpdateAI across the thread pool — one worker per Lua state — then a serial UpdateAI pass. Most AI runs multithreaded.
LUA HumanAI.lua → NativeHumanAI:Update()
A ~10-line entry script hands off to the real controller object. (Crabs, turrets, dropships and rockets each have their own equivalent.)
LUA behaviour coroutines
The dispatcher watches the actor's AIMode and runs up to two behaviour coroutines, drawing on the HumanBehaviors / SharedBehaviors libraries.
LUA Controller:SetState(...)
The behaviour's only output: it sets the actor's Controller — the same buttons and analog sticks a human holds.
C++ Actor locomotion / physics update
The engine reads that Controller and moves the actor — exactly as if a gamepad had sent the input.
C++ PathFinder (background thread pool)
In parallel, path requests the Lua AI raised resolve on a background pool; the result is handed back for a later tick.

1.2   The C++ / Lua split — the most important fact about this AI

The AI never moves an actor. It does exactly one thing each tick — set the actor's Controller, the same buttons and sticks a human holds. The engine then reads that Controller. The AI literally plays the game through the gamepad. That is why it is so moddable, and why so much of it is Lua:

The engine (C++) ownsThe Lua scripts own
The threaded per-tick invocation harness; the Controller input abstraction; the AIMode enum and waypoint storage. Every tactical decision. Which behaviour to run, and when to switch.
Sensing primitives — CastMORay, CastStrengthRay, LookForMOs — and the alarm-event list. Target acquisition, threat scoring, the "have I lost my target?" logic.
Pathfinding: the MicroPather A*, the node grid, the async request API. Path-following, locomotion, the jetpack-jump predictor, stuck handling, digging decisions.
Terrain-change tracking that feeds the pathfinder. All combat — aiming, target leading, fire / hold-fire, reloading, throwing, weapon choice.
The actor's own physics, locomotion gaits and damage model. Squad behaviour, alarm processing, tool / medikit use, gold-digging, brain-hunting.

The implication. The expensive low-level parts — pathfinding, sensing, threading — are in C++ and work. The brain, and crucially all path-following and locomotion, is Lua. That is the good news: the thing most in need of work is Lua, and Lua is where this overhaul mostly lives. The engine additions (§5) are small and few.

1.3   AI modes — the entire order vocabulary

The C++ AIMode enum (Actor.h) is the AI's whole vocabulary. A player's pie-menu order, an activity's spawn script — all any of them can say to an actor is one of these:

ModeApplies toWhat it does
SENTRYactorsHold position and facing; sweep aim; react to threats and alarms.
PATROLactorsWalk back and forth between obstacle-bounded extents.
GOTOactorsMove to a waypoint, then revert to SENTRY on arrival.
BRAINHUNTactorsSeek and destroy the nearest enemy brain.
GOLDDIGhumansScan for gold and dig toward it.

Six modes apply to fighting actors. That is the entire set of intentions a player or designer can express — there is no "hold this line", "breach here", "retreat", "rescue him", "mine that vein". Widening this vocabulary is a piece of the overhaul (§7, M5).

1.4   The behaviour engine — Lua coroutines

Within a mode, behaviour runs as Lua coroutines — not a behaviour tree, not a formal state machine. NativeHumanAI runs two coroutines at once: a main Behavior slot (combat, sentry, gold-dig) and a GoToBehavior slot (movement), so an actor can walk toward a target and shoot at the same time. A behaviour does one tick of work, calls coroutine.yield(), and after each yield checks an abort flag; to drop a behaviour the dispatcher resumes it once with that flag set. It works. (An in-source comment attributes the abort protocol to “memory leaks”; per upstream-dev review that note is inaccurate and carries no meaning — ignore it.)

BehaviourLibraryRole
GoToWptSharedBehaviorsThe ~657-line path-follower — the single most complex function in the AI. Walking, jumping, crawling, digging, stuck handling. The overhaul's main target.
ShootTargetHumanBehaviorsRanged combat — a real ballistic solver, target leading, aim-noise model, blast-radius safety. Capable.
SentryHumanBehaviorsGuard: face the likely approach, sweep aim, periodically sharp-aim, return to post.
AttackTarget / ThrowTargetHumanBehaviorsMelee / digger attack; grenade throwing with a ballistic solver.

1.5   Perception — two sets of eyes, decided at spawn

An actor gets one of two completely separate spotters, and which one is chosen once, in NativeHumanAI:Create:

  • LookForTargets — the default. Casts one ray, in a random direction, per AI tick (Owner:LookForMOs over a random 50–120° arc). An enemy can stand in the open and go unseen for many ticks. This is the design for ordinary actors.
  • CheckEnemyLOS — the good one. Boxes every enemy on screen and checks line-of-sight to one each tick, so it reliably sees anything on screen. Given only to brains, snipers, bosses and Nuts-difficulty actors.

So AI competence is bimodal: most enemies you fight run the random-ray spotter. Hearing is separate — weapons fire and explosions push AlarmEvents that ProcessAlarmEvent range-checks and occludes against terrain.

1.6   Locomotion & path-following — the heart of it

This is the subsystem the overhaul is really about. All ground movement runs through GoToWpt (SharedBehaviors.lua, ~657 lines — the largest function in the AI). It reads the engine-built path (Owner.MovePath), walks toward the next point, and pops points on arrival. For jetpack actors it runs a genuine trajectory predictor: it simulates four candidate jump arcs plus a "do nothing and fall" arc, casts obstacle rays along each, and jumps only if a jump beats falling by a margin. If the actor carries a digger and terrain blocks the path, it sweeps the digger across the obstacle.

It has two clear weak points, both verified in the source:

  • Stuck "recovery" is flailing. A StuckTimer notices the actor has stopped moving — and the "recovery" is to guess: a 15%-per-tick random lateral-direction swap, a 0.5%-per-tick random prone toggle, a random refuel. There is no diagnosis of why it is stuck, and no immediate re-path (re-pathing is on a separate 12–14 second timer).
  • It carries a known bug. In the follow-a-friendly path, an in-source comment reads -- WTF is the following code for? It causes us to idle and do nothing forever?? — a documented locomotion stall the developers themselves flagged and never resolved.

A path the pathfinder produced correctly is then followed badly — and that, multiplied across every actor, is what players see as "the AI is stupid."

1.7   Pathfinding — recently overhauled, and capable

Pathfinding is A* over a uniform grid of PathNodes via the third-party MicroPather library. Per upstream-dev review and a direct read of PathFinder.cpp, it is one of the stronger parts of the current AI:

  • It is fully async and multithreaded. CalculatePathAsync resolves on a background thread pool with a per-thread pather; it never blocks the main thread.
  • It reacts to terrain changes cheaply. A terrain edit recalculates only the affected node costs (RecalculateAreaCosts, capped per frame, run in parallel), with a cost-change epsilon so trivial changes — blood, debris — do not trigger resets.
  • It is jump-aware. Each actor passes its real JumpHeight (jetpack thrust vs. weight), and the pather expands genuine vertical and diagonal jump arcs. Terrain too hard for the actor to dig is weighted as a near-wall — intentional: dig what you can, route around what you cannot.
  • The per-path Reset() clears only MicroPather's solution cache (actors have different dig strengths, so costs are not shared) — not the graph. The pather object itself is created once per worker thread and reused. It is not "rebuilt constantly."

The v7 navigation overhaul already shipped. The development branch this fork is built on landed a substantial pathfinding & navigation overhaul (per CHANGELOG.md): jump-aware pathfinding, jetpack-aware ACrab and AHuman navigation with automover fallback, faster and smarter digging (dig toward the goal, route around undiggable rock), the Actor.JumpHeight property, and run / crouch locomotion states. Route-finding is in good shape. This plan starts from that baseline — its target is the layer above: actually following those routes.

1.8   Squad AI — there isn't any

There is exactly one squad mechanic, and it is not coordination. A squadmate standing near its leader literally copies the leader's controller states — NativeHumanAI loops a list {MOVE_LEFT, MOVE_RIGHT, BODY_JUMPSTART, BODY_JUMP, BODY_PRONE} and mirrors each from the leader, plus aim and fire. That is the whole of it. No roles. No formation. No spacing. No deciding who shoots whom. No shared knowledge. "Squad" means "stand near the leader and press the same buttons." When the leader dies, squadmates fall back to a cached waypoint or revert to sentry. This is why squads clump, friendly-fire and stall on each other — and it is upstream issue #208.

What is not broken — and stays. The combat behaviour (ShootTarget) is genuinely capable: a real ballistic solver, target leading, an aim-noise model, full-auto/semi handling, blast-radius safety, prone-shooting. The threat-scoring and behaviour dispatch are reasonable. The pathfinder is strong (§1.7). The AI's decision-making is not the problem — so the overhaul improves it where it is weak (perception, weapon choice) and otherwise leaves it alone. The problem is execution.

3  ·  The approach

The question for Cortex Command's AI is narrow, and an earlier draft of this page got it wrong. It is not "which prestige AI technique should the brain use." It is: what makes an actor reliably carry out a simple order — walk there, hold here, follow me, breach that — on destructible terrain. That is an execution question, and the answer is unglamorous work, not a new architecture.

3.1   The principle — fix execution, not the brain

  • Lead with locomotion. Path-following, jetpack control, stuck-recovery. It is the single biggest player-visible win and the thing players actually mean by "the AI is stupid."
  • Improve the decision Lua — do not replace it. The AIMode dispatch, the behaviour libraries and the combat AI are adequate-to-good. Targeted fixes (reliable perception, weapon scoring, alarm sanity) beat swapping a working dispatch for a scoring kernel.
  • Build on the engine's strengths. The async pathfinder, the Controller abstraction and the threaded harness work and were recently overhauled. Don't rewrite them.
  • Small, honest engine additions only — an emergency interrupt for the reflex layer, a lightweight danger query, the observability harness, a wider order vocabulary. Named and bounded in §5.
  • Most of the work is Lua, in Data/Base.rte/AI/. It means sitting down and making GoToWpt follow a path well — and that is exactly the point.
  • Gate everything on the harness (§8). "Better" is a number, not a vibe.

3.2   What this overhaul does not build

An earlier draft proposed a layered tower of prestige techniques. Upstream-dev review rejected it — it aims effort away from the actual failure. For the record, what is not being built, and why:

RejectedWhy
A pathfinder rewrite (D* Lite / LPA*, HPA*)The pathfinder is async, jump-aware and capable (§1.7), and was just overhauled. It is not the bottleneck. MicroPather stays; only small, targeted tweaks — not a rewrite.
A utility-AI architecture replacing the AIMode dispatchDecision-making is not the core problem. Replacing a working dispatch with a scoring kernel is large effort spent away from the locomotion failure players actually see.
An HTN commanderSquad coordination (M3) is real and needed — but as concrete squad logic (roles, spacing, shared targets), not a hierarchical planner layered over per-tick chaos.
An influence-map subsystem as a grand spatial world-modelOver-scoped. A small, targeted danger query for the reflex layer (M2) is kept; a general strategic-grid subsystem is not.
A behaviour-tree kernel replacing the coroutinesThe coroutines work. Consolidate the duplicated code (CrabBehaviors is a hand-copied fork) during the locomotion rework — no kernel, no migration.
Runtime ML / LLMs in the loopLatency, cost, non-determinism, offline play, modding breakage. Out (§9).

The governing principle: improve the Lua the AI already is; add the few small engine hooks it genuinely lacks; fix locomotion first. This keeps Lua — the fork's modding moat — intact (§6), keeps the change small enough to land milestone by milestone, and points the work straight at the failure players report.

4  ·  The shape of the work

The work is layered, but humble. Most of it is Lua in Data/Base.rte/AI/; the engine additions are small and named. There is no new decision "tower" — the layers below are simply where the fixing happens, in priority order, each independently verifiable, which is what makes the milestone plan (§7) possible.

L1
Locomotion & path-execution  [MOD]
The heart. Rework GoToWpt path-following: walk, climb, crawl, jetpack arc control, dig-through — an actor that actually carries out the route the pathfinder gave it. Almost entirely Lua.
Answers: bots flying into walls, hugging terrain, stalling — "the AI is stupid."
L2
Stuck-recovery & reflexes  [MOD][CODE]
Replace random flailing with a diagnosed recovery ladder. Add a reflex layer — dodge a live grenade, step off lava or a falling-rock arc, out of a friendly's line of fire — on a small engine emergency-interrupt and a lightweight danger query.
Answers: units stuck forever; units standing in obvious death.
L3
Squad coordination  [MOD]
Real squads: point / flank / support roles, useful spacing, shared target knowledge, the gatling-gun fix, and a squad that survives the leader's death. Concrete squad logic, in Lua.
Answers: clumping, friendly fire, no flanking (issues #208, #100).
L4
Perception & decision polish  [MOD]
Retire the bimodal spotter so every actor perceives reliably; score weapon and tool choice instead of string-matching; give alarms decay. Targeted improvements to the existing decision Lua — not a replacement.
Answers: blind bots, pistol-versus-tank, over-suppression.
L5
Orders & command  [MOD][CODE]
Widen the order vocabulary beyond the six-mode enum (hold, breach, retreat, rescue, mine…); a command UI for it; persistent orders that survive the player taking and releasing direct control.
Answers: a player can say only six things to a unit; manual control wipes its brain.
L0
Observability & replay — cross-cutting  [CODE]
Built first. A per-agent decision event log; an in-game overlay showing intent, target, path and current reason; the headless scenario runner and the trust suite. Small, bounded C++.
Answers: "the AI did something dumb and nobody knows why" — and it is what makes the AI testable without a human watching.

The pathfinder is deliberately not a layer here — it already works (§1.7). The engine is a near-fixed foundation; the overhaul is the Lua layers above it, plus the small L0 / L2 / L5 engine hooks detailed next.

5  ·  The engine work

This is the C++ side — and the honest headline is that it is small. There is no pathfinder rewrite and no new decision kernel. What the engine needs is a short list of bounded additions; everything else is Lua (§5.3).

5.1   What the engine work is not

For the avoidance of doubt: MicroPather stays and PathFinder.cpp is not rewritten; there is no utility-scoring kernel, no behaviour-tree kernel, no influence-map subsystem. The pathfinder is async, jump-aware and capable (§1.7); the decision layer is Lua and stays Lua. See §3.2 for why each was rejected.

5.2   The small engine additions

Each is a bounded C++ change with a thin Lua-facing surface. This is the whole engine scope of the overhaul.

5.3   Most of the overhaul is Lua

The locomotion rework (L1), the diagnosed stuck-recovery and reflex behaviours (L2), the squad coordination (L3), the perception and weapon-choice polish (L4) — all of it lives in Data/Base.rte/AI/*.lua: chiefly SharedBehaviors.lua (the ~657-line GoToWpt), HumanBehaviors.lua, NativeHumanAI.lua, and the crab equivalents. This is unglamorous work — reading a complex path-follower and making it follow paths well — and it requires sitting down and fixing things rather than writing a system with a big acronym. That is the overhaul. The engine additions in §5.2 exist only to give that Lua the two hooks it genuinely cannot do itself (an emergency interrupt, a danger query) and to make it all measurable (the harness).

Coordinate with the Multiplayer flagship (ADR-015)

Networked multiplayer is cortex-modern's second committed flagship (Multiplayer, ADR-015), and it depends on competent server-side AI. Two light couplings:

  • Build the small new C++ systems (§5.2) determinism-friendly. The event channel, the danger query and the order object are new simulation-adjacent state. Built with ordered iteration, a seeded RNG and no wall-clock, they cost the multiplayer build nothing; built carelessly they become determinism debt.
  • The harness is one apparatus. This flagship's M0 — the decision-event channel, the headless runner, CI — is most of the Multiplayer flagship's M0 sync harness. Build the observability harness once; both flagships gate on it.

6  ·  The mod surface

Cortex Command's modding ecosystem — twenty years of .rte mods on mod.io, Void Wanderers among them — is the fork's biggest asset. The overhaul is designed around it, not at its expense.

6.1   The AI stays Lua — which makes compatibility easy

Because this overhaul improves the existing Lua AI rather than replacing it with new engine kernels, the mod surface barely moves. There is no new registration API to learn, no behaviour-tree format to migrate to. Modders keep what they have: the per-actor ScriptPath hook (point an actor at the stock AI, or a fully custom one); the HumanBehaviors / SharedBehaviors libraries and the Create*Behavior factories; the Native*AI customization points; and the AIMode command API (SetAIMode, AddAISceneWaypoint, UpdateMovePath…) — widened, not broken; the old values stay valid. An actor on the stock AI simply gets the better locomotion, recovery and squad behaviour for free.

6.2   Will this break mods?

Existing AI mods fall into three categories; only one carries real risk.

A   Use the stock AI

The vast majority. Custom actors that point ScriptPath at the stock Base.rte/AI/HumanAI.lua (or Crab, etc.). They keep working — and their actors get the better AI for free.

B   Ship their own AI

Unaffected. A mod with a fully custom ScriptPath runs its own brain and never calls into anything the overhaul changes. ScriptPath is a hard opt-out.

C   Extend the stock AI

The risk category. Mods that require NativeHumanAI or override its internals depend on its exact shape — and the locomotion rework changes that shape. Covered by the facade and the legacy profile (§6.3).

6.3   Keeping mods working

Three safeguards, all cheap because the AI is just Lua files — the old version never has to be deleted:

  • The command-API facade. The Lua API mods drive the AI through (SetAIMode, AddAISceneWaypoint, UpdateMovePath, the AIMODE_* constants) is preserved as an explicit, tested facade; the widened order vocabulary is purely additive. Covered by old-API tests so it cannot silently drift. This keeps categories A and B working — and a corpus scan shows the real ecosystem (Void Wanderers et al.) leans almost entirely on this surface.
  • Behaviour-table preservation. The HumanBehaviors / SharedBehaviors tables and Create*Behavior factories keep their names and call shapes, so a category-C mod that overrides or wraps a behaviour still loads — its outcome improves, its hooks resolve.
  • The legacy profile. The entire pre-overhaul AI — every behaviour file, unchanged — is frozen and packaged as an opt-in Legacy AI profile, selectable per-actor via ScriptPath. A mod that depends on the old AI's exact behaviour pins to it. The escape hatch for any mod.

Compatibility is measured, not promised. From milestone M1 the validation harness loads and runs the community mod corpus (the local cccp_mods/ set — Void Wanderers, the Mappack and BB+, ~3,500 files) on every CI cycle, against the pre-overhaul baseline recorded in M0. If a mod breaks, the report names the exact call — and the fix is one of: repair the facade, pin the mod to the legacy profile, or help it migrate. "Does Void Wanderers still work" is a line in the definition of done and a green light on every build.

7  ·  The plan — milestones to completion

How this plan is scoped

Sequenced by dependency and gated by validation — not by calendar time. The build is executed by AI coding agents; the meaningful units are what must exist first and how we know it is done. Every milestone states what it depends on and the exact, machine-checkable condition that closes it. An agent picking up this build starts at M0. Each milestone is a complete, shippable improvement, and the build always contains a working AI better than the milestone before. The order is locomotion-first: M1 alone — actors that follow paths — is the largest single jump in perceived AI quality.

8  ·  Validation — proving the AI, without watching it

An overhaul this size is only as trustworthy as its test regime. The plan is built so the result is proven, not vibed — and proven almost entirely without a human in the loop. That is why M0 builds the test apparatus first. The harness is not an afterthought; it is the instrument that lets AI coding agents build the AI at all, because it is the thing that decides, automatically, whether a change made the AI better or worse.

8.1   The AI thinks out loud

Because every decision emits a structured event, tests assert on the cognition stream, not on pixels. The decision-event schema — the thing M0 builds — is roughly:

event = {
  tick      = <sim frame>,
  actor     = <actor id>,
  layer     = "reflex" | "locomotion" | "squad" | "decision",
  type      = "behaviour_selected" | "target_acquired" | "path_failed" | "stuck" | ...,
  chosen    = "advance_to_waypoint",
  reason    = "path clear, next node reachable on foot",
  target    = <actor id or position>,
}

You never watch the AI; you read what it decided and why. "Did any actor emit engage against a friendly?" → fail. "Did one emit stuck and never recover?" → fail.

8.2   The trust scenario suite

Twelve hand-authored scenarios, each a scripted scene + an order + behavioural pass/fail assertions, run headless. They are the spine of the suite — and most of them test execution:

#ScenarioWhat it proves
AI-01Defend the brain roomHolds position, reacts to alarms, does not abandon the post without an order.
AI-02Breach a doorSelects a breaching tool or a penetrating weapon; does not waste ammo on what it cannot dent.
AI-03Dig to an objectiveEquips a digger, cuts a viable tunnel toward the goal, does not seal itself in.
AI-04Recover from a collapsed tunnelDetects the stale path and replans / digs / retreats within a deadline.
AI-05Suppress an alarmInvestigates or suppresses only when plausible — does not chase every noise.
AI-06Rescue a downed unitExtracts, covers, or flags it impossible — never idles.
AI-07Avoid a dropship crushClears an obvious landing path when warned.
AI-08Hold formation through a bunkerThe squad keeps useful spacing — no clumping, no stalling on each other.
AI-09Use a medikitHeals when safe; interrupts and defends when threatened.
AI-10Weapon pickupSeeks a nearby weapon when it is genuinely better than the current one.
AI-11Retreat from an unwinnable breachReports the objective impossible instead of looping on it forever.
AI-12Cross a newly-opened routeFollows a route that did not exist until terrain changed — the locomotion layer and the live pathfinder working together.

Every scenario runs on destructible terrain, with both friendly and enemy AI, and every run records a replay and the full reason log.

8.3   Statistical pass/fail — flaky becomes rigorous

Cortex Command's simulation is non-deterministic, so a test cannot assert exact state. Instead each scenario runs K times and asserts on rates with a confidence bound — "holds the brain in ≥ 95% of runs", "friendly-fire incidents ≤ X per run on average", "no actor stuck > N seconds in ≥ 98% of runs". Non-determinism stops being a problem to fight and becomes a property the suite measures around. m_ForceImmediatePathingRequestCompletion can pin pathing to complete synchronously, removing one source of run-to-run variance for the tighter tests.

8.4   Self-play, regression & the mod corpus

The new AI is run against itself, against the old AI, and against prior versions of itself — across many maps, many times, unattended. Self-play surfaces emergent stupidity scripted scenarios miss (mutual stalemate, suicidal rushes, two sides both stuck). New-vs-old win rate is a single number for "are we winning"; new-vs-previous-version catches regressions the moment they appear. From M1 the harness also loads and runs the cccp_mods corpus (Void Wanderers, the Mappack, BB+ — §6.3) every cycle; the compatibility guarantee of §6.3 is a test, not a promise.

8.5   Fuzz & invariant testing

Beyond the twelve authored scenarios, the harness procedurally generates scenes — random terrain, random placements, random orders — and asserts invariants that must hold everywhere: no actor is ever stuck beyond N seconds, no actor ever fires through a friendly, every actor always carries a current reason label, no behaviour ever hard-loops or crashes. Fuzzing finds the long tail the authored scenarios cannot.

8.6   The autonomous loop

The harness emits a machine-readable report — per-scenario pass/fail, the full metric set, and a saved replay for every failure. It runs in CI on every change. An AI coding agent works the loop directly: edit the AI → the harness grades it → read the report → iterate, with the failure replays pointing at exactly which decisions went wrong. The harness is the fitness function — it is what makes an agent-driven build of something this large tractable, because "better" is never a judgement call. It doubles as an offline tuner: wrap it in a search over the AI's tuning parameters (recovery thresholds, spacing distances, alarm-decay rates) and keep the set that scores highest.

8.7   What the harness measures

MetricWhat it catches
Objective completion rateWhether the AI actually does the job it was given.
Mean time-stuck per actorThe single most-reported failure — bots jammed on terrain.
Path-completion rateWhether actors reach where they were sent — the core locomotion metric.
Friendly-fire incidents per runCoordination and line-of-fire awareness.
Squad spacing / clumpingWhether squads hold useful formation.
Damage taken from avoidable hazardsWhether the reflex layer is doing its job.
Self-play stalemate rateEmergent passivity — two competent AIs that never resolve.

8.8   Where the human stays

The human role shrinks to three things the machine cannot do: authoring the scenarios and setting the pass thresholds; spot-checking the saved replays of failures the agent could not resolve; and the final, irreducible "is it fun" judgement. The machine checks against the bar; the human sets the bar.

9  ·  What not to do

  • Don't rewrite the pathfinder. It is async, jump-aware, capable and recently overhauled (§1.7). The player-visible failures are downstream of it, in locomotion. MicroPather stays.
  • Don't build a decision tower. Utility AI, HTN, an influence-map subsystem, a behaviour-tree kernel — decision-making is not the core problem, and that effort is spent away from the failure players actually report. (§3.2.)
  • Lead with the unglamorous work. Path-following and stuck-recovery are "sitting down and fixing things," not a system with a big acronym. That is the overhaul — do not let it slip behind prestige work.
  • Don't rip out Lua. The mod ecosystem is the fork's biggest asset; the overhaul improves the Lua — it never deletes it.
  • No LLMs or runtime ML in the tactical loop. Latency, cost, non-determinism (it would break replays and the Multiplayer flagship), offline play, modding breakage. ML earns its keep in exactly one place — the harness's offline tuner (§8.6) — and never in the runtime loop.
  • Don't read architecture into stray code comments. An earlier draft of this page did, and was wrong. Verify a claim against the source and against the people who wrote it before acting on it.
  • Don't skip the harness. M0 comes first, always. An AI you cannot measure cannot be built to a finish line — and each milestone must be proven by the harness before the next is built on it.
Definition of done

The AI overhaul is complete — and not before — when all of the following hold:

  • The full AI-01..AI-12 trust suite is green at its target pass-rates, on destructible terrain, across every difficulty level.
  • Actors execute: across the fuzz set, mean time-stuck is near zero, the path-completion rate is high, and damage taken from avoidable hazards is low.
  • Squads hold useful spacing — no clumping — friendly fire is rare, and issues #208 and #100 are closed.
  • The fuzz harness finds no invariant violation across a large procedurally-generated scenario set, and large-scale AI-vs-AI self-play is stable over long runs and many maps.
  • A full side runs autonomously and competently with zero player input — and a player can take direct control of any unit and release it with no loss of intent.
  • The new AI is the Base.rte default; the community mod corpus — Void Wanderers included — still loads and runs, on the new AI or on the preserved opt-in legacy profile.
  • Every shipped decision is explainable: it carries a reason, and it can be replayed.

That is the finish line. It is specific, it is measured by machine, and it does not move.
