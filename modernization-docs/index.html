Cortex‑Modern Modernization Effort

A working wiki, plan and decision tracker for modernizing our fork of the Cortex Command Community Project.

The headline finding

This is not a 2007 codebase. The development branch we forked is an unreleased v7.0 carrying ~2 years of un-shipped modernization: SDL3, a new OpenGL/raylib GPU renderer, multithreaded Lua scripting, a new adaptive-music engine, a pathfinding overhaul, compressed saves, and the removal of the old multiplayer.

So the real task is not "modernize an old game" — it is "finish a modernization that is already ~70% done." The remaining 30% is a small set of deeply-rooted architectural cores, mapped precisely in the Technical Analysis.

Three layers of "old"

Every recommendation in this wiki sorts into one of three layers. The effort should target Layer 3 and avoid Layer 2.

LayerStateExamples
1 — Already modern DONE SDL3, GPU renderer (draw is "negligible"), multithreaded Lua/AI, MusicMan, navigation overhaul, compressed .ccsave, Tracy profiling, C++20
2 — In-flight on branches UPSTREAM WIP GPU-renderer rewrite, Box2D + WebAssembly port, two-stage fog-of-war — mostly dormant, single-author branches; see Upstream Branches
3 — Untouched 2007 DNA OUR TARGET 8-bit palette model, single-threaded atom physics, Allegro 4 as a bitmap library, luabind, RakNet, the legacy GUI toolkit

How to use this wiki

This is git-tracked plain HTML — no build step, no server. The git history of modernization-docs/ is the change history of the plan.

  • Add a work item → edit the WORK_ITEMS array in tracker.html, commit.
  • Record a decision → add an ADR card to decisions.html, commit.
  • Update findings → edit analysis.html / roadmap.html, commit.

Keep edits small and commit often.
