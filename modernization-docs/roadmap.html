Modernization Roadmap

Work sorted into three tiers by effort and risk. Tier 1 ships independently and fast; Tier 3 is strategic and slow. Each item maps to a row in the Work Tracker.

Tag legend

[MOD] Lua / INI / data, no recompile   [CODE] a bounded C++ engine change   [ARCH] a large rework or new simulation core   [DEP] a dependency swap or upgrade   [BUILD] a build-system change

Upstream branches — what's already in flight

Upstream development is frozen since 2026-04-06; the real work lives in unmerged, mostly single-author WIP branches, none mergeable as-is. The full per-branch deep-dive is on the Upstream Branches page. One branch feeds this plan directly: the original interpolated-render holds the real interpolation work and is design reference for T2-01. The sol3 branch compiles a luabind→sol2 port but — per upstream-dev review — is not a re-executable template: it breaks vanilla and modded Lua (see T2-02).

TIER 1   Quick wins — low risk, ship independently

[DEP]  T1-01   Bump security-sensitive dependencies

libpng 1.6.40→1.6.58, zlib-ng→2.2.x, LZ4→1.10, minizip-ng→4.0.10, LuaJIT (pinned beta3 has CVE-2024-25176). These parse untrusted mod and (formerly) network data. Drop-in upgrades.

Effort: low · Risk: low · minizip-ng has one known API break (mz_compat.h).

[CODE]  T1-02   Gamepad rumble / haptics

Wire SDL_RumbleGamepad into UInputMan, expose to Lua so weapons, explosions and damage trigger feedback. SDL3 is already in place; nothing calls rumble today. High game-feel payoff, purely additive.

Effort: low-medium · Risk: low

ABSORBED  T1-03   Multiplayer code & RakNet

Once a standalone “delete the dead networking code” task, then held pending the multiplayer decision. That decision is made (ADR-015): the ~5,900 lines of removed networking code and RakNet are kept as the reference implementation, and milestone M1 of the Multiplayer flagship rebuilds the server spine and retires RakNet for a modern transport. No longer a standalone item.

Status: absorbed into the Multiplayer flagship · see the Multiplayer page & ADR-015

[CODE]  T1-04   Delete dead GL code

Stubbed GLResourceMan::CompileShader, commented-out m_Blit8 shader, the vestigial 16bpp MOID-layer constant. Clarifies the renderer with zero behaviour change.

Effort: trivial · Risk: none

[CODE]  T1-05   Audio terrain occlusion

A 2D destructible-terrain game where dirt does not muffle gunfire. Reuse the existing AI strength-ray to drive an FMOD lowpass + volume per channel. Big immersion win, isolated and additive.

Effort: medium · Risk: low

[MOD] [CODE]  T1-06   Squad AI — absorbed into the AI flagship

Originally scoped here as a Tier-1 pure-Lua squad-AI tweak. It has since been promoted: AI is cortex-modern's flagship, and "smarter squads" is one milestone (M3) of a locomotion-first AI overhaul — fix path-following and stuck-recovery first, then squads, then a perception & decision pass, mostly in Lua. The committed plan, the seven milestones and the automated test suite are on the dedicated AI page.

Status: superseded by the AI flagship · see the AI page & ADR-014

[BUILD]  T1-07   Build reproducibility fixes

Pin the empty PlatformToolset to v143; remove stale SDL2 packages from the Meson CI workflow (it installs SDL2 while the build uses bundled SDL3).

Effort: trivial · Risk: low

TIER 2   Medium — bounded, high value

[CODE]  T2-01   Render interpolation

Store previous transform, lerp by accumulator / deltaTime at draw time. Kills motion stutter when refresh ≠ 60 Hz. m_PrevPos already exists, and HeliumAnt's renderer work made the draw phase near-free. Scope it to single-threaded interpolation — interpolated-render-redux had exactly this premise (interpolation without the thread split that sank the original) but barely started; mine the original interpolated-render for the lerp and teleport/wrap code. Per the upstream lead the real difficulty is making input handling async — inputs must be processed at the display framerate independent of the sim-tick rate.

Effort: medium · Risk: medium — thread an alpha through every Draw, handle teleports/wrapping, and design the async-input model

[DEP]  T2-02   luabind → sol2/sol3

Removes the worst dependency and the Boost requirement. The upstream sol3 branch compiles a luabind→sol2 port — but per the upstream lead it is not a re-executable template: sol2 changes usertype property and constructor semantics in ways that break vanilla Lua and the entire mod corpus (sol2 issue #1513). The real work is solving that compatibility break, which collides with ADR-004's mod-compatibility rule — a compatibility shim may be larger than the ~5,100-LOC port itself.

Effort: high · Risk: high — the sol2 mod-compatibility break is the real problem, not the port; reassess whether it is worth doing at all

[BUILD]  T2-03   Build all deps from source

Set use_prebuilt_libraries=false everywhere, stop committing .lib blobs. This eliminates the __iob_func hack at its root.

Effort: medium · Risk: medium

[CODE]  T2-04   GPU sprite drawing for MOs

Make MOSprite::Draw / MOSRotating::Draw use DrawTexturePro (already proven in BitmapPrimitive::Draw) instead of software draw_sprite into the shared 8bpp layer. Recolour modes become shader uniforms.

Effort: large · Risk: high (touches every MO subclass) — partly gated by §1.1

CORRECTED  T2-05   Profile multithreaded Lua scripts

An earlier read claimed threaded MO script timings were invisible to PerformanceMan. Per the upstream lead that is wrong — PerformanceMan already tracks them (ScriptTiming / UpdateSortedScriptTimings), as wall-clock time across all scripts rather than per-core CPU-time, and that is by design. The item is effectively closed; a per-core breakdown would be a minor optional add, not a needed fix.

Status: corrected / closed — the premise was inaccurate

TIER 3   Strategic — the real modernization

[ARCH]  T3-01   Multithread the physics travel loop

The performance ceiling. Particles travel near-independently — parallelize them against a read-only terrain snapshot with deferred-write command buffers. (An earlier version suggested adopting the box2d-emscripten direction; the upstream lead advises against a Box2D physics switch — CC's atom physics is core identity and that branch never matured. Parallelizing the atom-travel loop is the path.)

Effort: very high · Risk: very high

[ARCH]  T3-02   Decouple the material map from the palette

The keystone (§1.1). Give terrain a dedicated single-channel material-ID buffer independent of an RGBA colour layer. Unblocks 32-bit colour, >256 materials, and ultimately retiring Allegro.

Effort: very high · Risk: very high — the single highest-leverage change

[ARCH]  T3-03   Rebuild BuyMenu / editors / Metagame UI

The dated UX all rides the legacy Allegro GUIControlManager. A unified modern UI toolkit (the PieMenu shows the team can build good UI) modernizes purchasing + editing + campaign together.

Effort: very high · Risk: high

[ARCH]  T3-04   Multiplayer — the networked-play flagship

Reopened by ADR-013, now a committed flagship (ADR-015): server-authoritative state replication, staged. A Steam Remote Play stopgap ships immediately; co-op is built via state replication with terrain sent as semantic commands over a determinism island (M1–M4); the island then grows whole-tick toward rollback PvP (M5–M6). The committed plan — seven milestones (M0–M6) with file touch-points, the engine work, and the automated sync harness — is the dedicated Multiplayer page.

Status: committed plan — see the Multiplayer page & ADR-015

[ARCH]  T3-05   Retire Allegro 4

Once material map, terrain, sprites and blends are off indexed BITMAPs, replace BITMAP with an engine-owned surface type and drop the abandoned Allegro fork. Depends on T3-02.

Effort: very high · Risk: very high · ~56 files / 477 call sites

Beyond modernization — the Corefall feature track

The three tiers above are engine modernization. A second, independent axis runs in parallel: feature and content expansion, mined from the sister project Corefall. Its large [MOD] tier — deeper AI and squad command, causal damage, loot, factions, a mission-director / storyteller layer — ships as ordinary .rte mods with no engine fork, so it does not compete with Tier 1–3 for engine work; T1-06 is already its first item. The full catalogue, the rationale, and what to leave alone are on the Corefall Ideas page and in ADR-010.

The flagship of that track is a real strategic Campaign — now a committed plan (ADR-012): "The Frontier", a strategic war map evolved from the abandoned "Conquest" mode plus a persistent tactical company campaign that finishes Cortex Command's own unfinished story. The committed plan — six ranked visions, the architecture, seven milestones (M0–M6) and the validation suite — is the dedicated Campaign page.

And the foundational flagship — the one the Campaign and co-op Multiplayer both stand on — is the AI overhaul. It is a locomotion-first overhaul: mostly [MOD] work fixing the AI's Lua — path-following, stuck-recovery, squads, perception — with a small set of [CODE] engine hooks. It has its own committed milestone plan and is recorded as ADR-014.

The contributor sweet spot

Given a tiny upstream team and mod-compatibility fears, the highest-return work is: all of Tier 1, plus render interpolation (T2-01) and the luabind→sol migration (T2-02).

It is real modernization, it is un-owned (not on an active upstream branch), every item is individually mergeable, and none of it fights the team's mod-compatibility constraints. Tier 3 is where the deep wins are — but each Tier-3 item is a project in itself and should only start once a Tier-3 decision record commits to it.
