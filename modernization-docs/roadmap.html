Modernization Roadmap

Work sorted into three tiers by effort and risk. Tier 1 ships independently and fast; Tier 3 is strategic and slow. Each item maps to a row in the Work Tracker.

Tag legend

[MOD] no recompile   [CODE] C++ change   [ARCH] large rework   [DEP] dependency   [BUILD] build system

What the maintainers already own — do not duplicate

The upstream branch list is an unwritten roadmap. These efforts are active (commits Feb–Apr 2026). Competing with them wastes effort and creates merge conflicts.

  • box2d-emscripten — phased Box2D v3.1.0 integration for object physics + a WebAssembly port.
  • emscripten-port — a working browser / iOS build.
  • gpu-renderer — the next renderer iteration (HUD on GPU, split-screen).
  • interpolated-render-redux — render interpolation.

Stalled & un-owned (1,600+ commits behind — effectively dead): sol3 (luabind replacement), hot-reloading, gles-v2. These gaps are where an outside contributor has the most room — we can pick them up.

TIER 1   Quick wins — low risk, ship independently

[DEP]  T1-01   Bump security-sensitive dependencies

libpng 1.6.40→1.6.58, zlib-ng→2.2.x, LZ4→1.10, minizip-ng→4.0.10, LuaJIT (pinned beta3 has CVE-2024-25176). These parse untrusted mod and (formerly) network data. Drop-in upgrades.

Effort: low · Risk: low · minizip-ng has one known API break (mz_compat.h).

[CODE]  T1-02   Gamepad rumble / haptics

Wire SDL_RumbleGamepad into UInputMan, expose to Lua so weapons, explosions and damage trigger feedback. SDL3 is already in place; nothing calls rumble today. High game-feel payoff, purely additive.

Effort: low-medium · Risk: low

[CODE] [DEP]  T1-03   Resolve the orphaned multiplayer island

~5,000 LOC of NetworkServer/Client + Multiplayer* activities is compiled in but unreachable, and it drags in the abandoned RakNet dependency. Either delete it cleanly (removing RakNet) or formally decide to rebuild it — today it is the worst of both.

Effort: low-medium · Risk: low · see ADR — pending

[CODE]  T1-04   Delete dead GL code

Stubbed GLResourceMan::CompileShader, commented-out m_Blit8 shader, the vestigial 16bpp MOID-layer constant. Clarifies the renderer with zero behaviour change.

Effort: trivial · Risk: none

[CODE]  T1-05   Audio terrain occlusion

A 2D destructible-terrain game where dirt does not muffle gunfire. Reuse the existing AI strength-ray to drive an FMOD lowpass + volume per channel. Big immersion win, isolated and additive.

Effort: medium · Risk: low

[MOD]  T1-06   Smarter squad AI & difficulty depth

Squad AI only copies the leader's controls. Add real squad roles (point / flank / support), coordinated suppression, and difficulty that scales reaction time and target priority — all in Base.rte/AI/*.lua. No engine change, fully mod-overridable.

Effort: high (pure Lua) · Risk: low

[BUILD]  T1-07   Build reproducibility fixes

Pin the empty PlatformToolset to v143; remove stale SDL2 packages from the Meson CI workflow (it installs SDL2 while the build uses bundled SDL3).

Effort: trivial · Risk: low

TIER 2   Medium — bounded, high value

[CODE]  T2-01   Render interpolation

Store previous transform, lerp by accumulator / deltaTime at draw time. Kills motion stutter when refresh ≠ 60 Hz. m_PrevPos already exists. Revive the interpolated-render-redux work as a reference.

Effort: medium · Risk: medium (thread an alpha through every Draw; handle teleports/wrapping)

[DEP]  T2-02   luabind → sol2/sol3

Removes the worst dependency and the Boost requirement. The stale upstream sol3 branch shows the shape (SolObjectWrapper, split binding files) — re-execution, not invention. ~5,100 LOC of bindings + the execution core.

Effort: high · Risk: high (binding-semantics parity) — highest-value single change

[BUILD]  T2-03   Build all deps from source

Set use_prebuilt_libraries=false everywhere, stop committing .lib blobs. This eliminates the __iob_func hack at its root.

Effort: medium · Risk: medium

[CODE]  T2-04   GPU sprite drawing for MOs

Make MOSprite::Draw / MOSRotating::Draw use DrawTexturePro (already proven in BitmapPrimitive::Draw) instead of software draw_sprite into the shared 8bpp layer. Recolour modes become shader uniforms.

Effort: large · Risk: high (touches every MO subclass) — partly gated by §1.1

[CODE]  T2-05   Profile multithreaded Lua scripts

Script timings are only recorded for the master Lua state; the bulk of per-frame scripting (threaded MO updates) is invisible to PerformanceMan. Make timings thread-safe / merge per-state.

Effort: low · Risk: low

TIER 3   Strategic — the real modernization

[ARCH]  T3-01   Multithread the physics travel loop

The performance ceiling. Particles travel near-independently — parallelize them against a read-only terrain snapshot with deferred-write command buffers. Or adopt the maintainers' box2d-emscripten direction rather than competing with it (see ADR-005).

Effort: very high · Risk: very high

[ARCH]  T3-02   Decouple the material map from the palette

The keystone (§1.1). Give terrain a dedicated single-channel material-ID buffer independent of an RGBA colour layer. Unblocks 32-bit colour, >256 materials, and ultimately retiring Allegro.

Effort: very high · Risk: very high — the single highest-leverage change

[ARCH]  T3-03   Rebuild BuyMenu / editors / Metagame UI

The dated UX all rides the legacy Allegro GUIControlManager. A unified modern UI toolkit (the PieMenu shows the team can build good UI) modernizes purchasing + editing + campaign together.

Effort: very high · Risk: high

[ARCH]  T3-04   Decide multiplayer's future

If multiplayer returns, it should be real server-authoritative state-replication netcode with client-side prediction — not the old screen-streaming model. Requires an entity-replication layer the engine does not have.

Effort: very high · Risk: very high

[ARCH]  T3-05   Retire Allegro 4

Once material map, terrain, sprites and blends are off indexed BITMAPs, replace BITMAP with an engine-owned surface type and drop the abandoned Allegro fork. Depends on T3-02.

Effort: very high · Risk: very high · ~56 files / 477 call sites

The contributor sweet spot

Given a tiny upstream team and mod-compatibility fears, the highest-return work is: all of Tier 1, plus render interpolation (T2-01) and the luabind→sol migration (T2-02).

It is real modernization, it is un-owned (not on an active upstream branch), every item is individually mergeable, and none of it fights the team's mod-compatibility constraints. Tier 3 is where the deep wins are — but each Tier-3 item is a project in itself and should only start once a Tier-3 decision record commits to it.
